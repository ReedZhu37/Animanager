# Animanager 功能迭代计划

日期：2026-11-16  
状态：P0 已完成；P1 的导出选项、缩略图与属性筛选已接入 App 和 Limbo Console。回归入口分别为 `Test.ps1 -Suite LibraryP0` 和 `Test.ps1 -Suite P1`。

目标是先把现有动画素材管理和使用流程补齐，再扩展素材兼容范围，最后推进重定向与动画加工。本计划只安排功能，不包含界面视觉重做。P0 已完成；本轮推进 P1 的导出选项与缩略图 / 属性筛选，暂缓人物与武器预设管理。骨架切换和重定向另行安排。

## 1. P0 开始前的功能基线

- 已有 FBX、GLB、glTF 及部分 UE4 / UE5 `.uasset` 的本地导入、批处理队列、取消和失败重试。
- 已有名称与标签搜索、单项标签和收藏、动画播放与定位、骨骼和轨迹检查、Root Motion 路径显示。
- 已有单项 FBX / GLB / RES 导出；批量导出目前为 FBX。
- Nodachi 740 条动画已完成独立人体与武器轨道存储、同步播放、握持偏移与接触区间保存。737 条含武器轨道，3 条使用明确标记的参考姿势。
- Nodachi 使用固定的 161 骨骼人体定义及共享 Manny Mesh，未把源武器骨骼加入人体。当前武器显示为 App 自有参考刀，接触信息不执行 IK。
- 磁盘上可存在多个独立 Library，启动参数可选择库；App 当前一次绑定一个库，没有运行中切库功能。
- 当前 `.motion` 有来源归档、共享对象校验、元数据副本和展示配置修订历史；完整动画版本管理、自动索引重建和旧库迁移尚未实现。

存储现状以 [Nodachi 独立轨道说明](MOTION_STORAGE.md) 为准；[动画存储规划](ANIMATION_STORAGE_PLAN.md) 中尚未实施的结构不算现有能力。

## 3. P0 功能范围

### 3.1 多 Library 管理

支持登记多个库，每次打开一个活动库。每个库保持独立、完整，可整体搬迁。

计划功能：

- 新建空库、登记已有库、查看库名称及实际路径。
- 切换活动库、记住最近打开的库；首次使用仍可指定启动库。
- 为库建立稳定身份，登记表保存在应用配置中；库内相对资产路径继续有效。
- 现有库首次接入时兼容原数据库和文件，保留资产 ID、标签、收藏及任务记录。
- 对路径失效、库损坏、重复登记和备份副本的库身份冲突提供明确处理结果。
- 运行中的任务先等待结束或明确取消完成，再切换库。切换时清理旧预览、选择和回调，避免把操作结果写入另一个库。
- UI 与 Limbo Console 共用库管理服务，并能查询当前活动库。

本轮不做同时挂载多个库、跨库联合搜索、跨库复制工具或跨库共享对象池。

验收标准：

1. 在 Nodachi 与 Movement 现有库之间切换，无需退出程序或重新导入。
2. 切换后列表、预览、任务记录和当前库名称一致；修改标签只影响对应库。
3. 重启后能恢复最近打开的有效库；库路径失效时能重新定位或选择其他库。
4. 显式 `--data-dir` 优先于最近打开记录，测试与专用启动脚本仍能指定独立库。

### 3.2 资产整理

计划功能：

- 修改资产显示名称，不重命名按哈希保存的底层对象。
- 完整的资产多选，批量添加 / 移除标签、设置收藏；覆盖选中范围要明确。
- 创建自定义集合，同一资产可属于多个集合；集合只保存引用，不复制动画数据。
- 将资产移入回收站并恢复，保留原 ID、名称、标签、收藏、集合归属及展示配置。
- 永久删除前检查所有有效资产和保留历史的引用；共享人物 Mesh、骨架及动画对象不能随单条资产误删。
- 名称、标签、收藏及集合等持久元数据具备可恢复记录，为索引重建提供依据。

验收标准：

1. 批量整理选中的动画，不影响未选中项；操作在重启后保留。
2. 同一动画加入多个集合不会复制底层文件，移出集合不删除资产。
3. 删除并恢复 Nodachi 样本后，其身份、标签、握持配置和接触区间一致。
4. 删除一个引用共享预设的资产后，其他动画仍能正常播放与导出。

### 3.3 基础库维护

计划功能：

- 检查清单、必要对象、文件大小、哈希及索引引用；发现问题后列出具体受影响资产。
- 生成一致的库备份，包含数据库、持久元数据、对象、预设、源归档及保留的配置历史；备份过程协调写入任务。
- 将备份恢复到独立位置，校验后登记和打开，不覆盖正在使用的库。
- 从持久元数据重建索引。旧资产只有 SQLite 元数据时，先在数据库健康状态下补齐可恢复记录。
- 区分持久数据、转换中间输出和预览缓存。提供清理预览、空间统计及明确的删除范围。
- 只清理已完成任务的可再生成中间文件；在用数据、源归档、回收站及保留修订引用的对象不作为普通缓存清理。

若旧数据库已经损坏且没有元数据副本，应报告无法恢复的字段，不能承诺找回原标签与收藏。

验收标准：

1. 将 Nodachi 库备份并恢复到新目录，原下载目录不可用时仍能播放人体和武器动画。
2. 在隔离副本中重建索引，资产数量、ID、名称、标签、收藏和集合关系保持一致。
3. 缺失或损坏对象被准确报告，完好资产仍可使用。
4. 清理转换缓存后，动画预览、握持配置、接触信息及导出结果保持一致。

## 4. P0 实施顺序与完成条件

虽然库维护排在第 3 项，其数据基础需要与前两项一起设计，尤其是库身份、持久元数据和共享对象引用关系。

| 里程碑 | 内容 | 完成条件 |
| --- | --- | --- |
| M1 | 库身份、登记表、活动库会话和切换 | 现有两个库可以反复切换，任务和状态不串库 |
| M2 | 资产整理及可恢复元数据 | 批量整理、集合、删除和恢复可用，共享对象保留正确 |
| M3 | 校验、备份恢复、索引重建和缓存清理 | 在隔离副本验证恢复及清理，原始库不受影响 |
| M4 | App / Limbo 接入与整体验收 | 两个入口调用同一业务逻辑，现有导入、播放和导出流程通过回归 |

P0 完成的用户流程：打开 Nodachi 库 → 搜索并多选动画 → 批量整理到集合 → 删除并恢复样本 → 切换 Movement 库 → 切回 Nodachi → 备份并恢复到另一目录。

不得把“只增加库选择菜单”作为多库完成，也不得把“仅复制 SQLite”作为完整库备份。

## 5. 后续阶段边界

### P1 使用现有素材

本轮范围（2026-11-16 确认）：

- 暂缓人物与武器预设管理，不增加武器配置或跨骨架切换入口。
- 完善单项和批量 FBX / GLB / RES 导出，支持 Mesh、已有片段、时间范围及输出采样帧率；参数随任务保存，失败重试沿用原参数。保留已支持的 Nodachi 独立武器轨道，不增加武器管理入口。
- 自动生成可再生成的预览缩略图；支持骨架、时长和源帧率筛选，与名称 / 标签、分类和集合共同生效，先筛选再分页。
- 导出与浏览操作使用 App / Limbo 共用服务。所有验证使用隔离库和输出目录。

本轮验收：

1. 多选资产批量导出 GLB / RES；FBX 继续使用 Blender，同名输出自动编号。
2. 选择片段、裁剪或重采样后，重新读取输出可验证片段名称、时长与采样结果；原动画、预览状态和共享骨架不变。
3. 属性依据实际解析结果，时长为资产中最长片段；无法确定的源帧率显示未知，不用预览播放速度代替。
4. 缩略图缓存复用且可清理重建；翻页、筛选和切库不会应用过期结果或改变布局。
5. 既有右键删除 / 恢复、多选、库维护与导出流程通过对应回归。

后续预设范围：

预设管理先支持已验证的同骨架兼容人物和刚性道具。切换预设不得改写源轨道；不同人体比例或不兼容骨架必须等待重定向支持。握持配置要明确对应道具预设、坐标基准及适用规则，不能对不同武器直接复用未经校验的数值。

导出配置优先支持仅人体 / 带武器、是否包含预设 Mesh、选择已有动画片段及批量 GLB / RES。时间范围裁剪和重采样只先作用于导出产物；保存为新的库内派生动画归入 P3 动画加工。导出参数不得改写原始资产。

缩略图作为可再生成缓存。筛选属性来自实际解析结果，区分源帧率与播放速度；未解析属性显示未知。

### P2 扩展真实素材覆盖

武器规则按真实样本逐类实现，保留源轨道与映射依据。额外武器规则不得扩充固定人物的蒙皮骨架，也不得自动引入素材包的 Mesh。

导入兼容性按文件版本、编码和骨架分别判断。优先处理实际使用素材的阻塞项；RAR 入口、更多 AnimSequence 编码、Montage 和其他运行语义分别立项，不以“UE5 素材”笼统承诺全支持。

握持辅助先做可复用校准和接触区间编辑。自动接触识别保留人工确认与修正；接触 IK 作为显式处理步骤，不改变已保存的原始转刀轨道。

### P3 重定向 动画加工与远程库

跨骨架 Retarget 同时考虑人体映射、道具参考空间、握持和接触约束，用真实素材比较处理前后结果。

动画加工保存为可追溯的派生结果，保留原始数据与处理参数。远程库在本地库身份、恢复和版本规则稳定后推进，不能仅凭现有存储接口认定已具备云同步能力。

## 6. 共同约束与回归

- 保留 Limbo Console；新业务操作由共用服务提供，界面不单独实现一套数据逻辑。
- `.uasset` 导入与已有动画播放继续不依赖本机 Unreal；FBX 导出沿用 Blender 管线。
- 保留固定人物骨架和 Mesh，人体及武器始终共用播放时间轴。
- 现有导入去重、取消和失败重试保持有效；自动续跑不计入 P0 完成条件。
- 用隔离库副本验证删除、恢复、索引损坏和缓存清理；保留原始素材与现有验证库。
- 回归覆盖 Nodachi 转刀、人物骨架与蒙皮不变、UE4 / UE5 标准导入及现有 FBX 导出。
- 按实际改动运行对应检查，不因只修改文档启动实现或整包转换。
